# このプロジェクトの目的

このプロジェクトの太源の目的は、ユーザーの小説制作活動に寄与することである。

既存の設定と各段階のプロットを根拠として、制作進行中の chapter の本文をエピソード単位で執筆し、物語全体の整合性を保ちながら完成へ進める。

# 対象と範囲

- 制作進行中の chapter を対象とする。
- chapter 全体は約10万文字、25エピソードで構成する。
- 各エピソードは約4000文字を目安とする。
- 各エピソードの本文は、対応するプロット詳細を中心に、上位のプロットと設定を踏まえて創作する。
- 各エピソードの本文は個別の `.txt` ファイルへ保存する。
- 本文執筆中に新たな恒常設定が生じた場合は、適切な設定ファイルへ追記する。
- プロット自体の全面的な再設計は、ユーザーから明示的に依頼された場合を除いて行わない。

# 情報源

次の順序で必要な情報を確認する。

1. `<git root>\index.md`
   - 設定ファイルの所在と構成を把握するための索引として使用する。
   - 本文執筆に必要な設定は、索引から対応する原資料を特定して確認する。
2. `<git root>\plot\chapter-plot\plot-overview-<chapter>.md`
   - 対象 chapter 全体の目的、開始状態、主要展開、終着点を把握する。
3. `<git root>\plot\chapter-plot\plot-intermediate-<chapter>.md`
   - 対象 chapter を構成する各エピソードの役割、順序、概略を把握する。
4. `<git root>\plot\episode-plot\plot-detail-<chapter>-<episode>.md`
   - 執筆対象エピソードの具体的な出来事、場面、因果関係、登場人物の行動を把握する。
5. 既に作成済みの同 chapter の本文
   - 文体、人物の口調、直前までの状態、既出情報、伏線、時間・場所の連続性を確認するために参照する。

`<chapter>` と `<episode>` には、制作対象の識別子をそのまま使用する。

## 情報源の扱い

- `index.md` は索引として使用し、重要な設定は可能な限り索引先の原資料で確認する。
- 下位のプロットは上位のプロットを具体化する資料として扱う。
- `plot-detail` は具体的な場面を補うために使用するが、chapter 全体の目的や確定済み設定を独断で変更する根拠にはしない。
- 現在のユーザー指示が既存資料と明示的に異なる場合は、現在のユーザー指示を優先する。
- 資料間に重大な矛盾があり、どちらを採用するかで物語の展開や設定が変わる場合は、推測で解消しない。
- 軽微な不足は、既存設定・人物像・因果関係に反しない範囲で補完する。

# 基本方針

- プロットを単に文章化するのではなく、小説本文として自然に読める場面へ具体化する。
- 出来事の列挙ではなく、人物の行動、反応、会話、知覚、判断、感情の変化を通して物語を進める。
- 各エピソードは単独の場面集ではなく、chapter 全体の流れの一部として機能させる。
- 既存設定、人物像、時系列、因果関係、伏線との整合性を優先する。
- 説明のためだけの不自然な会話や、既知情報の重複説明を避ける。
- 先の展開に必要な情報は、読者が理解できる範囲で自然に配置する。
- プロットにない大きな事件、人物、能力、組織、世界設定を、本文を盛り上げる目的だけで追加しない。
- 新たな要素を追加する場合は、そのエピソードの成立に必要であり、既存設定と矛盾しないものに限る。
- 各エピソードの約4000文字は目安とし、場面の自然な区切りを壊してまで文字数を合わせない。
- 25エピソード全体で約10万文字になることを意識し、序盤だけを過度に膨らませない。

# 制作対象の決定

- ユーザーが chapter と episode を指定した場合は、その対象を執筆する。
- chapter のみ指定された場合は、原則として episode 1 から 25 まで順番に処理する。
- 既存本文がある場合は、未完成のエピソードだけを対象とし、完成済み本文を独断で上書きしない。
- 制作対象を一意に特定できない場合は、既存ファイルから明確に判定できる範囲のみ進める。

# 作業手順

1. `<git root>\index.md` を読み、本文執筆に関係する設定ファイルを特定する。
2. 必要な設定ファイルを確認し、人物、世界、場所、物事、用語、能力、関係性などの確定事項を把握する。
3. `<git root>\plot\chapter-plot\plot-overview-<chapter>.md` を読み、chapter 全体の役割と到達点を把握する。
4. `<git root>\plot\chapter-plot\plot-intermediate-<chapter>.md` を読み、25エピソードの流れと各エピソードの役割を把握する。
5. 執筆対象について `<git root>\plot\episode-plot\plot-detail-<chapter>-<episode>.md` を読み、具体的な展開を把握する。
6. 既に前のエピソードの本文が存在する場合は確認し、次の項目を引き継ぐ。
   - 登場人物の現在位置
   - 時刻・日付・経過時間
   - 所持品
   - 負傷・疲労・服装などの状態
   - 人物関係と感情
   - 既に読者へ開示した情報
   - 未回収の伏線
   - 直前の場面から継続する行動や目的
7. 対象エピソードの本文を創作する。
8. 本文中で新たな恒常設定が生じた場合は、`index.md` を参照して対応する設定ファイルを特定し、重複を避けて追記する。
9. 本文と設定の更新後、対象エピソードについて整合性を確認する。
10. 次のエピソードを続けて制作する場合は、更新後の設定と完成した本文を前提として同じ手順を繰り返す。

# 本文の判断基準

各エピソードでは、少なくとも次を満たす。

- `plot-detail` にある主要な出来事が本文上で成立している。
- エピソードの開始状態と終了状態の変化が分かる。
- 登場人物の行動に、その人物なりの目的または理由がある。
- 重要な結果には、読者が追える原因がある。
- 会話、行動、描写のいずれかが、人物・状況・物語の進行に寄与している。
- 同じ情報を必要なく繰り返していない。
- 前後のエピソードと人物の状態や時系列がつながっている。
- chapter 全体の目的へ進んでいる。
- プロット上必要な伏線、準備、情報開示が欠落していない。
- 後続エピソードで必要になる確定事項を、本文だけに閉じ込めず必要に応じて設定ファイルにも反映している。

# 新しい設定の扱い

本文執筆によって新しい設定が必要になった場合は、次の条件で設定ファイルへ追記する。

## 追記するもの

- 人物の恒常的な属性、能力、過去、関係
- 地名、施設、地域の恒常的な特徴
- 世界の法則、制度、文化、技術、魔法体系
- 後続エピソードでも再利用される物品、組織、用語
- 物語上、以後の整合性維持に必要な確定事項

## 原則として追記しないもの

- その場限りの比喩や情景描写
- 一時的な姿勢、視線、感情の細部
- 後続の整合性に影響しない背景描写
- 既存設定の言い換え
- まだ本文上で確定していない推測

設定を追記するときは、既存の記法、見出し、分類、表記に合わせる。

# 出力先

各エピソードの本文は、次のファイルへ保存する。

`<git root>\text\text-<chapter>-<episode>.txt`

- 1エピソードにつき1ファイルとする。
- `.txt` には小説本文のみを記述する。
- 作業報告、解説、評価、注釈、Markdownの見出しは本文ファイルへ混在させない。
- 章題やエピソード題を入れる場合は、既存作品の形式またはユーザー指定に従う。
- 既存ファイルを更新する場合は、利用環境で安全に更新できる方法を使用する。

# 完成前の自己検証

各エピソードの保存前に内部で確認し、問題があれば修正する。

- 設定と矛盾していないか。
- `plot-overview` のchapter全体の流れを損なっていないか。
- `plot-intermediate` で定めたエピソードの役割を満たしているか。
- `plot-detail` の主要事項を落としていないか。
- 前話から人物、場所、時間、所持品、負傷、情報量が自然につながっているか。
- 後続エピソードに必要な条件を壊していないか。
- 新しく生じた恒常設定を適切な設定ファイルへ反映したか。
- 本文中に作業メモやメタ説明が混入していないか。
- 文章量が約4000文字を大きく外れていないか。外れる場合は、場面構成上の必要性があるか。
- 25エピソード全体で約10万文字という規模感から著しく偏っていないか。

# 例外・制限

- 参照対象のファイルが存在しない場合は、その内容を推測で作ったことにして進めない。
- 必須の設定やプロットが不足していても、影響が軽微なら既存情報から自然に補完する。
- 不足や矛盾によって主要人物の行動、物語の結末、世界設定などが大きく変わる場合は、独断で確定しない。
- 既存の設定や完成済み本文を、執筆上の都合だけで変更しない。
- ユーザーから明示的な変更指示がある場合を除き、ファイル名、パス、`<chapter>`、`<episode>` の識別形式を変更しない。
