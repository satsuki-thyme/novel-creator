# このプロジェクトの目的

ユーザーの小説制作活動に寄与することを最上位の目的とし、制作進行中の chapter について、既存設定と章プロットの概要を踏まえた中間粒度のエピソード構成を作成・管理する。

# 対象と範囲

- 制作進行中の chapter を、章全体で約10万文字となるよう25エピソードに分割する。
- 各エピソードは約4000文字を目安とし、物語上の役割に応じて増減してよい。
- 各エピソードについて、本文執筆の土台として使えるプロットの概略を作成する。
- プロット作成中に確定した新しい設定は、対応する設定ファイルへ追記する。
- 本文そのものは、ユーザーから明示的に依頼されない限り作成しない。

# 情報源

次の順に参照する。

1. 現在の依頼でユーザーが明示した内容
2. 制作進行中の chapter のプロット概要
   - `<git root>\plot\chapter-plot\plot-overview-<chapter>.md`
3. `<git root>\index.md` から特定した既存の設定ファイル
4. 同一 chapter に関係する既存資料

## 設定の参照

1. 最初に `<git root>\index.md` を確認する。
2. インデックスから、今回の chapter に関係するキャラクター、場所、世界設定、物事、その他の設定ファイルを特定する。
3. 結論に必要な設定は、インデックスの記述だけで判断せず、対応する設定ファイル本文を確認する。
4. 参照できないファイルの内容を推測で補わない。

# 作業手順

1. 制作進行中の chapter を特定する。
2. `<git root>\index.md` と、そこから特定した関連設定ファイルを確認する。
3. `<git root>\plot\chapter-plot\plot-overview-<chapter>.md` を確認し、次を把握する。
   - 始まりの状態
   - 主要な出来事と因果関係
   - 主人公の変化
   - クライマックス
   - 終わりの状態
   - 必ず維持すべき設定・伏線・制約
4. 章全体を25エピソードに分割する。
5. 各エピソードが前後につながり、章全体の因果関係と感情の流れが段階的に進むよう構成する。
6. 各エピソードについてプロットの概略を作成する。
7. 25エピソード全体を通して、約10万文字の章として成立する配分になっているか確認する。
8. 完成した内容を `<git root>\plot\chapter-plot\plot-intermediate-<chapter>.md` に反映する。
9. 作業中に新しく確定した設定を抽出し、`<git root>\index.md` から対応する設定ファイルを特定して追記する。
10. 更新後、プロットと設定ファイルの間に矛盾や重複がないか確認する。

# エピソード分割の判断基準

- 原則として25エピソードすべてに、物語上の変化または次の展開へつながる役割を持たせる。
- 単なる移動、説明、会話だけで独立させず、状況・関係・認識・目的・危機のいずれかが変化する単位として構成する。
- 章プロットの概要にある重要な出来事を勝手に削除、逆転、置換しない。
- 概要にない出来事は、既存設定と矛盾せず、概要の因果関係・クライマックス・終着点を補強する場合に創作する。
- クライマックスへ向けて、障害、選択、失敗、発見、関係変化などを段階的に積み上げる。
- 各エピソードの終わりには、可能な範囲で次のエピソードを読む理由となる未解決事項、決断、発見、変化のいずれかを置く。
- 各エピソード約4000文字は目安とし、25エピソード合計で約10万文字になることを優先する。
- 重要度の低い出来事を水増しして文字数を合わせない。

# 新しい設定の扱い

- プロット作成のために新しく導入し、今後も継続して有効となる情報だけを設定として扱う。
- 一時的な演出、未確定案、単発の行動は設定ファイルへ追記しない。
- 既存設定と同じ内容は重複して追記しない。
- 既存設定と矛盾する新設定が必要になった場合は、既存設定を独断で書き換えず、まずプロット側を既存設定に合わせる。
- ユーザーの明示した新しい内容が既存設定と矛盾する場合は、ユーザーの最新指示を優先し、必要な設定更新を行う。
- 設定の保存先は `<git root>\index.md` の分類と参照先に従う。
- 適切な保存先を特定できない場合は、推測で新規ファイルを作らず、未反映の設定として報告する。

# 出力形式

`<git root>\plot\chapter-plot\plot-intermediate-<chapter>.md` は、原則として次の形式にする。

```markdown

- 想定文字数: 約100,000字
- エピソード数: 25
- 1エピソードの目安: 約4,000字

## Episode 01: <短い見出し>

- 想定文字数: 約<数値>字
- 開始時の状況: <text>
- 主な展開:
  - <text>
  - <text>
- 主人公・主要人物の変化: <text>
- 次への接続: <text>

## Episode 02: <短い見出し>

- 想定文字数: 約<数値>字
- 開始時の状況: <text>
- 主な展開:
  - <text>
  - <text>

- <章の終わりで成立している人物・状況・関係・目的など>
```

# 整合性の確認

完成前に次を確認する。

- 25エピソードすべてが存在する。
- 章全体の想定文字数がおおむね10万文字になる。
- 各エピソードの出来事が前後の因果関係でつながっている。
- `<git root>\plot\chapter-plot\plot-overview-<chapter>.md` の主要な流れを維持している。
- 既存設定に反する人物像、能力、時系列、場所、制度、世界法則を導入していない。
- 同じ役割のエピソードや展開の重複が必要以上に続いていない。
- クライマックスまで緊張、困難、選択、情報開示などが段階的に進んでいる。
- Chapter終了時の状態が概要で定めた終わりの状態と一致している。
- 新しく確定した設定が、必要な設定ファイルへ反映されている。
- 設定ファイルへの追記によって既存内容との重複や矛盾が生じていない。

# 情報不足・例外

- 制作進行中の chapter を既存ファイルや現在の依頼から一意に特定できない場合は、作業結果を大きく左右するためユーザーに確認する。
- `plot-overview-<chapter>.md` が存在しない、または章の主要な流れを判断できないほど情報が不足している場合は、推測で中間プロットを確定しない。
- 一部の設定ファイルだけ参照できない場合は、参照できる情報で安全に進められる範囲まで作業し、影響する箇所を明示する。
- ファイル更新に必要な操作は、利用環境と上位の指示に従い、安全に実行する。
