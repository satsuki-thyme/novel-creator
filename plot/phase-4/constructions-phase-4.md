# このプロジェクトの目的

ユーザーの小説制作活動に寄与することを主要な目的とし、制作進行中の chapter について、既存の設定・章全体のプロット概要・各エピソードの概略を基に、本文執筆に利用できる各エピソードの詳細プロットを作成する。

# 対象と範囲

- 制作進行中の chapter を対象とする。
- chapter 全体は約100,000文字を想定する。
- chapter を25エピソードに分割し、各エピソードは約4,000文字を想定する。
- 各エピソードについて、本文執筆の土台として使える詳細プロットを1ファイルずつ作成する。
- 詳細プロットの作成に伴って新たに確定した継続的な設定は、対応する設定ファイルへ追記する。
- 小説本文そのものの執筆は、ユーザーから明示的に依頼された場合を除き、このプロジェクトの対象外とする。

# 情報源

次の順に参照する。

1. `<git root>\index.md`
   - 設定ファイルの構成、参照先、作品全体の情報配置を把握するために使用する。
2. `<git root>\plot\chapter-plot\plot-overview-<chapter>.md`
   - 制作進行中の chapter の全体的なプロット概要を把握するために使用する。
3. `<git root>\plot\chapter-plot\plot-intermediate-<chapter>.md`
   - 制作進行中の chapter を25分割した各エピソードの概略を把握するために使用する。
4. `index.md` から参照できる既存の設定ファイル
   - キャラクター、場所、世界設定、物事、その他の既存設定を確認するために使用する。

現在の依頼でユーザーが追加・変更した内容がある場合は、それを最優先する。

参照先が存在しない、内容を取得できない、または必要な情報が不足している場合は、確認できない内容を推測で既存設定として扱わない。作業を進められる範囲は進め、重要な不足だけを明示する。

# 基本方針

- 既存の設定、章プロット、エピソード概略との整合性を優先する。
- `plot-intermediate-<chapter>.md` に定められた各エピソードの役割、順序、主要出来事を維持したまま詳細化する。
- 新しい出来事、伏線、対立、感情変化、情報開示、場面転換などは、章全体の流れを補強する範囲で追加する。
- 前後のエピソードが因果関係でつながるようにする。
- 各エピソード単独でも、開始時点から終了時点までに何らかの変化または進展が生じる構成にする。
- 重要な出来事や情報を、一つのエピソードへ過度に集中させない。
- 各エピソード約4,000文字で本文を書けるだけの内容量を確保するが、詳細プロット自体を本文の文章量まで膨らませない。
- 既存設定と矛盾する内容を必要とする場合は、独断で設定を変更せず、矛盾として示す。

# 作業手順

1. `<git root>\index.md` を参照し、設定ファイルの構成と参照先を把握する。
2. `index.md` から必要な設定ファイルを参照し、制作進行中の chapter に関係する設定を把握する。
3. `<git root>\plot\chapter-plot\plot-overview-<chapter>.md` を参照し、chapter 全体の目的、開始状態、主要な展開、クライマックス、終了状態を把握する。
4. `<git root>\plot\chapter-plot\plot-intermediate-<chapter>.md` を参照し、25エピソードそれぞれの概略と前後関係を把握する。
5. chapter 全体を通して、各エピソードの役割、因果関係、情報開示、感情変化、伏線と回収の配置を確認する。
6. エピソード1から25まで順番に詳細プロットを作成する。
7. 各詳細プロットを次のファイルへ分割して入力する。
   - `<git root>\plot\episode-plot\plot-detail-<chapter>-<episode>.md`
8. 詳細化によって新しく確定した設定を抽出する。
9. 新しい設定が継続的に参照される情報である場合は、`index.md` に示された対応する設定ファイルへ追記する。
10. 全25エピソードを通して、章全体のつながり、設定との整合性、重複、矛盾、展開の抜けを確認し、必要なら詳細プロットを調整する。

# 各エピソードの詳細化

各エピソードでは、少なくとも次の内容が把握できるようにする。

- エピソードの目的
- 開始時点の状況
- 主な登場人物
- 主な場所
- 起こる出来事の流れ
- 主人公または主要人物の行動
- 対立、障害、問題
- 感情または関係性の変化
- 読者へ新たに提示する情報
- 必要な伏線、再提示、回収
- エピソード終盤の転換または到達点
- 次のエピソードへつながる要素
- 本文約4,000文字で展開する際の重点

出来事の数は固定しない。エピソードの役割に応じて、必要な場面数と密度を設定する。

# 詳細プロットの形式

各ファイルは、原則として次の形式で記述する。

```markdown
# Episode <episode>

## 目的

<このエピソードが chapter 全体で果たす役割>

## 開始時点

<開始時の状況、人物の状態、場所など>

## 展開

1. <出来事・行動・反応>
2. <出来事・行動・反応>
3. <必要なだけ追加>

## 人物・感情・関係の変化

- <人物または関係>: <開始時から終了時までの変化>

## 情報開示・伏線

- <新しく示す情報、再提示する伏線、回収する要素>

## 終了時点

<エピソード終了時の状態と到達点>

## 次エピソードへの接続

<次のエピソードへ持ち越す問題、目的、疑問、行動など>

## 本文執筆時の重点

- <約4,000文字で描写するときに重点を置く点>
```

内容に不要な項目は削除してよいが、出来事の流れと開始・終了の変化が分からなくならないようにする。

# 新しい設定の扱い

詳細プロット作成中に新しい設定が必要になった場合は、次の基準で扱う。

- 以後の物語でも参照される人物設定、場所、制度、能力、物品、世界の仕組みなどは、対応する設定ファイルへ追記する。
- そのエピソード内だけで完結する行動、台詞、演出、偶発的な出来事は設定ファイルへ追記しない。
- 既存設定の変更になる場合は、新規設定として追記せず、既存内容との矛盾を確認する。
- 追記先は `<git root>\index.md` に従って決定する。
- 適切な追記先を特定できない場合は、独断で新しい設定ファイルを作らず、その設定と追記先未確定であることを示す。

# 判断基準

詳細プロットを作成するときは、次を満たすことを優先する。

- chapter 全体の目的と各エピソードの役割が一致している。
- 25エピソードの順序に明確な因果関係がある。
- 各エピソードに状態、関係、認識、目的のいずれかの変化がある。
- クライマックスへ向けて緊張、課題、情報、感情が段階的に積み上がる。
- 伏線や情報開示が必要な時点より早すぎたり遅すぎたりしない。
- 同じ機能の場面や出来事を不必要に繰り返さない。
- 約4,000文字で本文を書いたとき、過密にも希薄にもならない内容量になっている。
- 既存設定を不用意に変更していない。

# ファイル更新

- 既存ファイルを変更する場合は、ユーザーのファイル更新に関する共通指示に従う。
- 新規の詳細プロットファイルは、`<git root>\plot\episode-plot\plot-detail-<chapter>-<episode>.md` の形式で作成する。
- `<episode>` の表記形式は既存ファイルやプロジェクト内の命名規則がある場合はそれに合わせる。
- 既存の詳細プロットファイルがある場合は、その内容を確認してから更新し、ユーザーの意図しない消去を行わない。

# 出力

作業完了時は、次を簡潔に報告する。

- 対象とした chapter
- 作成または更新した詳細プロットファイル
- 設定ファイルへ追記した内容と対象ファイル
- 未解決の矛盾または不足がある場合はその内容

同じ内容をチャット本文へ重複して全文掲載する必要はない。
